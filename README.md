# Set-Based Learning with Emergent Label Dynamics

This repository contains the implementations and experiments comparing Deep Sets, Set Transformer, Janossy Pooling and PointNet++ for a neighbourhood-based classification task. The models are evaluated on a synthetically generated dataset and the CiteSeer citation network. In addition to classification performance, class-specific metrics, accuracy as a function of node degree, and training and inference times are recorded.

The most important directories and files contain:

- `data/`: Pre-processed datasets and the raw CiteSeer data generated by PyTorch Geometric
- `src/model_code/`: Implementations of the four model families, as well as the training and evaluation functions used in common, are contained in `deepset.py`
- `src/data_set_prep_code/`: Scripts for creating datasets, parameter search and aggregation of test results
- `results/standalone_checkpoints/`: Checkpoints from individual model scripts runs
- `results/model_evaluation/`: Results of the complete series of experiments -> Each run has its own directory for the dataset, model, configuration and seed
- `run_all_experiments.sh`: Runs all the model configurations examined in the report on both datasets
- `report/`: Report and architectural diagrams

A successfully completed experimental run normally contains the following files:

```
seed_<SEED>/
├── command.txt
├── training.log
├── metrics.json
├── <checkpoint>.pt
└── SUCCESS
```

`command.txt` records the command that was executed, `training.log` contains the console output and `metrics.json` contains the extracted metrics. The model state and other results are saved in the checkpoint. An empty file named `SUCCESS` indicates a successfully completed run. If a run fails, a file named `FAILED` is created instead.

## Requirements

Python 3.10 or later and an up-to-date Bash environment are recommended. The script `run_all_experiments.sh` is primarily intended for use on Linux or WSL. The Python packages used directly are listed in `requirements.txt`, along with the versions of the environment used for the experiments.

An NVIDIA GPU is not strictly necessary, but it can speed up the experiments. To run the experiments on the GPU, a version of PyTorch compatible with the local CUDA installation must be installed. The CUDA and NVIDIA packages for the original virtual environment are not specified individually in `requirements.txt`, as they depend on the operating system, hardware and PyTorch distribution. If the CUDA environment differs, PyTorch should first be installed following the relevant installation instructions.

## Installation on Linux

The repository can be downloaded using Git. The placeholders must be replaced with the actual repository address and directory name.
```
git clone https://github.com/Annemarie-Weise/deeplearningpython.git
cd path/to/deeplearningpython
```
You can then create and activate a virtual Python environment:
```
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

## Data sets

The two prepared datasets are already included in the repository:
```
data/SyntheticDataset/synthetic_dataset.pt
data/CiteSeer/citeseer_dataset.pt
```
It is therefore not necessary to regenerate the stored experiments. If the data sets are to be recreated, the following commands can be used:
```
python src/data_set_prep_code/dataset_reg_synthetic.py
python src/data_set_prep_code/citeseer_dataset.py
```
The default parameters of `dataset_reg_synthetic.py` match the final configuration used in the report. `citeseer_dataset.py` loads CiteSeer using PyTorch Geometric, converts the graph into an undirected graph, and saves the neighbourhoods in the common data format. The options available for a script can be displayed using `--help`:
```
python src/data_set_prep_code/dataset_reg_synthetic.py --help
```
The preliminary search for suitable parameters in the synthetic dataset can be carried out separately:
```
python src/data_set_prep_code/search_synthetic_parameters.py
```
By default, the results of this search are saved to `results/synthetic_parameter_results.csv`. The script does not automatically generate the final dataset that is subsequently used.

## Run individual models

Each model implementation can be run independently. The following example trains Deep Sets on the synthetic dataset:
```
python src/model_code/deepset.py \
    --dataset-path data/SyntheticDataset/synthetic_dataset.pt \
    --internal-features 128 \
    --epochs 50 \
    --learning-rate 0.001 \
    --seed 42 \
    --device auto
```
The `--device` option accepts `auto`, `cpu` or `cuda`. If set to `auto`, CUDA is used if a compatible GPU is available. Otherwise, the calculation is performed on the CPU.

The remaining template scripts are called up in the same way:
```
python src/model_code/janossy_gru.py --help
python src/model_code/pointnet_plus.py --help
python src/model_code/set_transformer.py --help
```

Unless a specific `--output-dir` is specified, the checkpoints for individual runs are stored in `results/standalone_checkpoints/`.

## Run complete test series

On Linux, the complete test suite can be run as follows: 
```
chmod +x run_all_experiments.sh
./run_all_experiments.sh
```

The script runs twelve model configurations on both datasets, using five seeds for each. This results in a total of 120 training runs, each comprising 50 epochs. The process is carried out sequentially and may take many hours, depending on the hardware and the device selected.
By default, the script uses `DEVICE=auto`. The desired device can be set explicitly:
```
DEVICE=cuda ./run_all_experiments.sh
```
or:
```
DEVICE=cpu ./run_all_experiments.sh
```

If you are using an environment that is not accessible by default via `python`, you can specify the interpreter using `PYTHON_BIN`:
```
PYTHON_BIN=.venv/bin/python ./run_all_experiments.sh
```

### Existing and new experiments

The repository contains previously saved experiment results. Before starting a run, `run_all_experiments.sh` checks whether a file named `SUCCESS` exists in the corresponding results directory. If so, the model is not retrained. Instead, the metrics are read from the existing checkpoint and recorded again in `summary.csv`.
To perform a complete recalculation of all configurations, the existing option `FORCE=1` should be used:
```
FORCE=1 ./run_all_experiments.sh
```

Alternatively, the relevant `SUCCESS` file can be deleted from a specific run directory if only that particular run should be repeated. The next time `run_all_experiments.sh` is called, only the run that is no longer marked as successful will be recalculated. 

### Aggregate results

`run_all_experiments.sh` creates or updates the non-aggregated file:
```
results/model_evaluation/summary.csv
```
Following new or repeated experiments, the mean values and sample standard deviations must be recalculated separately for each seed:
```
python src/data_set_prep_code/summarise_summary.py
```
By default, the aggregation script generates:
```
results/model_evaluation/summary_aggregated.csv
results/model_evaluation/precision_recall_aggregated.csv
```
`summary_aggregated.csv` contains the mean values and standard deviations of the numerical metrics for each combination of dataset, model and configuration. `precision_recall_aggregated.csv` contains the corresponding class-specific precision and recall values.
Custom input and output paths can be specified if required:
```
python src/data_set_prep_code/summarise_summary.py \
    --input-file results/model_evaluation/summary.csv \
    --output-file results/model_evaluation/summary_aggregated.csv \
    --class-metrics-output-file results/model_evaluation/precision_recall_aggregated.csv
```
